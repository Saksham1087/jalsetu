## Context

Complaint data flows through three views where users need PDF generation:
1. Right after submission (success confirmation)
2. User's complaint detail (bottom sheet)
3. Admin's complaint detail (full modal)

All three views have access to the full complaint object. PDF generation is a pure function of complaint data — no API calls needed.

## Goals / Non-Goals

**Goals:**
- Generate a professional-looking PDF with all complaint fields
- Lazy-load pdfmake so initial bundle is unaffected
- Work offline (no server dependency)
- One-click download (not print-to-PDF)
- Consistent PDF appearance across all three entry points
- File naming: `{userName}-{type}-{date}.pdf`

**Non-Goals:**
- No email delivery or sharing features
- No server-side PDF generation
- No bulk PDF generation
- No PDF preview before download

## Decisions

**Decision 1: pdfmake for PDF generation**
pdfmake provides structured document definitions with styled text, tables, images, headers/footers, and auto page breaks. Text is selectable in the generated PDF (unlike html2canvas approaches). The ~200KB footprint is acceptable since it's lazy-loaded only when the user clicks "Download".

**Decision 2: Image preloading**
pdfmake accepts image URLs but browser CORS may block cross-origin canvas reads. We preload images via fetch + blob + FileReader to get base64 data URIs, which pdfmake handles reliably.

**Decision 3: Download button in success auto-dismiss timeline**
The success view currently auto-dismisses after 2.4s. The download button stays within this view so users can download immediately. The auto-dismiss timer is not changed — if users miss it, they can always download from the list detail view.

**Decision 4: Download button in bottom action bar**
Both ComplaintDetail and AdminComplaintDetail have bottom action bars with status management buttons. The download button goes there, styled consistently with the existing button hierarchy.

**Decision 5: PDF layout**
PDF follows a clean report structure:
- Header: JalSetu branding + "Water Complaint Report" title
- Complaint ID + Status badge + Generation timestamp
- Sections: Type, Description, Location, Contact, Photo, Timeline
- Footer: "Generated by JalSetu" + page numbers

## Risks / Trade-offs

- pdfmake ~200KB lazy-load is acceptable for a PWA that already loads Leaflet, Firebase, Cloudinary widgets
- Cross-origin images may fail to load if Cloudinary CORS isn't configured — we gracefully skip images that fail to preload
- The success view download button has a narrow exposure window (2.4s) — users who miss it can download from the list view
